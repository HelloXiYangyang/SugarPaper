## 📖 项目简介

糖纸 · SugarPaper 是一款面向小学到高中学生的**多平台作业管理应用**。应用采用**离线优先 + 设备间 P2P 加密直连**架构，学习数据永不落盘到任何服务器，兼顾隐私与多设备同步需求。

**目标用户**：需快速录入作业并追踪进度的学生；在手机/平板/电脑间切换的多设备用户；重视隐私、不愿数据上云的学生和家长。

**核心价值**：
1. **秒级录入**：粘贴老师发的文本，自动解析为结构化作业清单。
2. **一键管理**：点击"完成"自动置底，进度一目了然。
3. **私密同步**：设备间通过局域网或点对点加密直连，数据不经过任何服务器。
4. **视觉治愈**：低饱和马卡龙色系，愉悦的使用体验。
5. **数据洞察**：日历视图和统计图表，让学习进度可视化。

**产品红线**（《统一开发方案 v5.0》）：① 不做自建服务器，账号=本地密钥；② 不做通用待办，只做学生作业场景；③ 不引入社交/排行榜，数据默认离线优先。

### ✨ 核心特性

- 📝 **文本解析导入**：粘贴老师消息 → 正则解析 → 预览 → 覆盖/追加导入
- 📄 **导入增强**：支持从 .txt/.md 文件导入、拖拽文本直接解析；拖入图片时明确提示 OCR 暂不支持并引导使用拍照存档
- 🧩 **解析增强**：中文数字编号（一、二、三）、打卡/背诵任务自动分类、未解析行导入纠错提示
- ✅ **任务管理**：进行中/已完成分组、完成/撤销动画、软删除、手动排序
- ⏰ **截止分级与逾期置顶**：任务按「已逾期 / 今天 / 明天 / 本周 / 长期」分组，逾期置顶标红并显示逾期天数
- 📸 **作业拍照存档**：任务可附带最多 4 张图片（拍黑板/作业存档，自动压缩，仅存本机并随加密快照同步）
- 🔍 **搜索与筛选**：关键词搜索 + 科目 Chip 筛选 + 优先级筛选
- 📝 **便签**：轻量速记（考试安排/老师通知/物品清单/回执模板），置顶/归档/颜色/标签/提醒、图片附件（最多 4 张）、Markdown 排版与编辑/预览切换、`- [ ]` 待办清单一键转作业（勾选项直接算完成）
- 🎤 **语音速记**：便签与作业导入支持语音输入（Web Speech API · zh-CN），说作业、说通知自动转文字
- 📅 **日历视图**：月/周切换、截止日期管理、日期格任务点、拖拽排期（桌面/平板）
- 🎯 **日历增强**：考试安排便签注入日历（标记显示），日期格专注分钟角标
- 📊 **统计图表**：整体进度环、每日完成趋势柱状图、科目分布饼图、历史趋势折线图；报告可导出 TXT 或 PNG 图片
- 📈 **数据洞察增强**：准时完成率（完成日 ≤ 截止日）、科目欠账按「未完成 + 逾期天数」加权排行、专注统计（分钟/番茄/连续天数/按科目聚合）
- 🍅 **番茄钟与专注场景**：任务卡一键开始专注、完成收获糖果；白/粉红/棕噪音与雨声/篝火/图书馆由 Web Audio 实时合成；呼吸引导、双音轨混音与自定义声音（上传本地音频 ≤2MB）
- 🧘 **专注模式独立界面（S12）**：番茄钟 + 白噪音独立一级 Tab（底部导航 6 项，专注居中，各 Tab 图标与样式统一）；中央计时环 + 场景渐变氛围 + 场景卡片网格 + 主音量/叠加音量 + 今日专注统计
- 🔄 **零服务器自动更新（S13）**：Web PWA 启动后读取 `updates/latest.json` 与本地版本号对比（`web/js/updater.js`），发现新版弹「立即刷新 / 更新记录」横幅，设置页「更新」卡片可手动检查；同时检测新版 Service Worker 外壳提示刷新；`updates/latest.json` 元数据 + GitHub Pages 部署 + Actions 标签发布流水线
- ⚖️ **首启强制用户协议（S14）**：首次打开必须阅读并勾选同意《用户协议》《隐私政策》后才能使用（不同意则无法进入）；「我的 → 法律与隐私」随时可查看两份协议
- 🎨 **主题化图标（S15）**：7 套主题各配一套图标主色/辅色，图标主体不变、颜色随主题切换（导航、卡片、主按钮、专注环、进度环同步换色）
- 📆 **作业日期快捷规划**：新建/编辑作业可选「今天 / 明天 / 后天 / 本周内 / 下周 / 长期 / 自定义」，由用户自主选择，新建默认当日
- 🔄 **自动升级弹窗（S17）**：打开后自动检查新版本，发现新版弹升级提示（忽略此版本 / 稍后再说 / 立即升级）；Service Worker 后台预缓存新版，点「立即升级」秒级生效
- 🔔 **提醒与数据安全网**：作业截止（前一晚 20 点/当天早 7-9 点/逾期即时）与便签提醒；超 7 天未导出备份时首页提示、存储用量可视化
- ⏰ **提醒时间自定义**：前一晚与当天早上提醒时间可在设置中调整
- 🔑 **无服务器账号与跨设备同步**：12 词助记词即账号（PBKDF2 → Ed25519，AES-256-GCM 端到端加密 + 签名防篡改）；Nostr 中继云端桥换设备登录即同步
- ⚡ **在线直连（P2P）**：同一账号两台在线设备经中继交换信令后建立 WebRTC DataChannel 直接互传加密快照，中继只转发信令
- 🏆 **激励体系（S18 模块一）**：连胜火焰、每日 XP 目标（类型/优先级计分 + 欠账双倍）、12 枚成就徽章墙、完成作业 XP 飘字与徽章解锁动画
- 🤝 **好友直连（S18 模块二）**：邀请交换共享密钥、端到端加密消息（AES-256-GCM）、分享作业一键导入，经 Nostr 中继转发密文，无中心服务器
- 👨‍👩‍👧 **家庭模式**：家庭成员助记词档案一键切换代管；打卡类任务家长确认
- 🧑‍🏫 **教师模式**：按标准格式排好作业（科目/条目/截止/优先级），一键复制或下载 .txt 发到班级群，学生粘贴进糖纸即可秒级导入
- 🎬 **动态动画**：动画默认全程开启（v0.29.0 起移除「动态动画」总开关）、帧率模式（自动/60/120）+ 流畅度自测、方向感知页面过渡、滚动显现缩放、按压缩放反馈、开关弹簧回弹、饼图转圈加载与扇区绽放、逐项淡入微动画、进度条流光，尊重系统"减弱动态效果"
- 🎨 **矢量图标**：全界面自绘 SVG 图标（24×24 描边风格随主题变色）、默认头像喜羊羊图片 + 自定义图片上传
- 🌙 **个性化**：主题自由切换（经典白 + 清新蓝绿/阳光黄桃/玫瑰粉/梦幻紫/薄荷绿 5 套马卡龙配色 + 暗色，7 套平行）、科目管理（内置小初高 16 学科）、通知提醒、JSON 导出/导入备份

### 🛠 技术栈

| 组件 | 选型 | 说明 |
| :--- | :--- | :--- |
| 前端 | 原生 HTML5 + CSS3 + JavaScript | 零构建、零依赖，双击 `index.html` 即可运行 |
| 存储 | `localStorage` | 离线优先，数据仅存本地（任务/科目/设置/头像） |
| 图表 | 内联 SVG | 进度环、柱状图、饼图、折线图，无第三方库 |
| 文本解析 | 纯正则解析引擎 | 科目行 / 编号条目 / 子行 / 优先级 / 截止日期；内置小初高 16 科词表 |
| 便签 / 番茄钟 / 专注场景 | `js/ui-notes.js` + `js/ui-focus.js` | 便签（置顶/归档/转作业）；番茄钟 + Web Audio 合成白噪音（雨声/篝火/图书馆）、呼吸引导与混音 |
| 账号身份 | `js/account.js` + Web Crypto | 12 词助记词 → PBKDF2 → Ed25519；AES-256-GCM 加密 + Ed25519 签名验签 |
| 云端桥同步 | `js/sync.js` + Nostr 中继（WebSocket） | 加密快照拉取/推送（kind 19322）、按 updatedAt 逐条合并、自动同步可开关 |
| 在线直连 | `js/sync.js` + RTCPeerConnection | 中继信令（kind 19323）+ WebRTC DataChannel P2P 互传加密快照 |
| 语音速记 | `js/ui-modals.js` + Web Speech API | 便签/导入弹窗语音转文字（zh-CN），浏览器不支持时自动隐藏 |
| Markdown 渲染 | `js/markdown.js` | 零依赖轻量渲染（标题/加粗/列表/待办清单/代码块/引用），先转义防注入 |
| 统计报告导出 | `js/report.js` + Canvas | SVG 报告卡片（进度环/摘要/专注/欠账排行）→ PNG 图片下载，零依赖 |
| 任务图片附件 | `js/ui-modals.js` + `js/ui-home.js` | 作业拍照存档（最多 4 张，压缩至最长边 512px，随加密快照同步） |
| 提醒时间配置 | `js/reminders.js` + `settings.reminder` | 前一晚 / 当天早上提醒时间可自定义（默认 20:00 / 07:00） |
| 导入增强 | `js/ui-modals.js` | 从 .txt/.md 文件导入、拖拽文本解析；图片拖入提示 OCR 暂不支持（零依赖约束） |
| 日历标记 | `js/stats.js` + `js/ui-calendar.js` | 考试安排便签标记 + 日期格专注分钟角标（纯函数 `dayMarkers`） |
| 教师模式 | `js/teacher.js` + `js/ui-teacher.js` | 作业文本生成器（科目行+编号条目+截止/优先级），复制/下载发班级群，学生粘贴即解析 |
| 自定义声音 | `js/ui-focus.js` + Audio(dataURL) | 上传本地音频为专注场景（≤2MB），可作主场景或叠加音 |
| 提醒引擎 | `js/reminders.js` + Notification API | 截止分级提醒 + 便签提醒，同条只提醒一次 |
| 响应式 | CSS 媒体查询五档断点 | Compact / Medium / Expanded / Large / XL |
| PWA | `manifest.webmanifest` + `sw.js` | 可安装、可离线（Service Worker 已实现，缓存应用外壳） |

### 🚀 快速开始

**方式一（零依赖）**：直接用浏览器打开 [`web/index.html`](./web/index.html)。

**方式二（本地服务）**：
```bash
node web/serve.js 8080
# 打开 http://localhost:8080
```

**运行测试**：
```bash
node web/test/unit.test.js          # 解析器 + 统计引擎单元测试
node web/test/e2e.test.js           # 端到端交互测试（需本机 Edge/Chrome + Playwright）
node web/test/screenshot.js         # 生成多断点界面截图至 web/test/shots/
node web/test/verify_docs.js        # 文档同步校验（16 科 + 头像：代码/PRD/README 三方一致）
```

cd app

APK 输出：`app/build/app/outputs/flutter-apk/app-release.apk`。

**构建同步约定（双向，自动执行）**：
1. **构建前**：`build_apk.ps1` 先从项目主仓库（`D:\项目\GitHub项目\SugarPaper\app`）**镜像同步**源码到英文构建目录（`D:\SugarPaper\app`，排除 build/.dart_tool/.idea），保证打包的永远是最新代码（镜像模式会删除主仓库已移除的文件，避免增量复制漏同步）。
2. **构建后**：安装包归档在英文构建路径（`D:\SugarPaper\...\flutter-apk\v<版本号>\`，release 构建必需）并**自动复制一份回主仓库同一位置**（`D:\项目\GitHub项目\SugarPaper\app\build\app\outputs\flutter-apk\v<版本号>\`）。
> 原因：release（AOT）构建在中文/非 ASCII 路径下会失败，故构建必须在英文路径 `D:\SugarPaper` 进行，产物经此约定自动同步回主仓库。

### 🚀 快速开始

**环境要求**：Flutter 3.22+、Visual Studio 2022（勾选「使用 C++ 的桌面开发」+ Windows 10/11 SDK）、**Windows 开发者模式**（Flutter 需要符号链接创建插件链接；不开开发者模式则需管理员终端）、Inno Setup 7（仅打包安装包时需要，本机已装于 `E:\Inno`）。

> ⚠️ **中文路径提示**：release（AOT）构建在中文/非 ASCII 路径下会失败（Flutter 已知限制）。本仓库位于中文路径时，请用纯英文路径的目录联接运行构建，例如：
> ```powershell
> New-Item -ItemType Junction -Path 'D:\SugarPaperDev' -Target '<本仓库路径>'
> cd D:\SugarPaperDev\app
> flutter build windows --release
> ```
> GitHub Actions（`windows-latest`）无此限制，正式发布走 CI 即可。

```powershell
cd app
flutter pub get
flutter test                 # 单元测试（与安卓版共享）
flutter build windows --debug    # 调试构建
flutter build windows --release  # 正式构建 → build\windows\x64\runner\Release\SugarPaper.exe
powershell -File build_windows.ps1            # 构建 + 绿色版 zip（归档到 dist\v<版本号>\）
powershell -File build_installer_windows.ps1  # 构建 + Inno Setup 安装包（归档到 dist\v<版本号>\）
```

## 🚀 发布规范：GitHub Releases（上传 / 命名 / 标题 / 内容）

> **规范范围**：本仓库各平台版本（安卓 APK、Windows 安装包、鸿蒙 HAP、网页版等）统一通过 [GitHub Releases](https://github.com/HelloXiYangyang/SugarPaper/releases) 发布；微信小程序除外（由微信平台审核发布）。各平台共用同一套「命名 + 标题 + 正文」约定，避免出现分不清版本、看不懂更新内容的情况。

### 📦 软件包命名规范

**统一格式**：

```text
SugarPaper-v<版本号>-<平台>[-<ABI>].<扩展名>
```

| 字段 | 说明 | 示例 |
| :--- | :--- | :--- |
| 应用名 | 固定 `SugarPaper`，与仓库名一致 | `SugarPaper` |
| 版本号 | 与 Release 标题、README 更新日志保持一致，必须带 `v` 前缀 | `v0.17.0` |
| 平台 | `android` / `windows` / `harmonyos` / `web` 等 | `android` |
| ABI（可选） | 安卓分 ABI 打包时标注；通用包不写 | `arm64-v8a` / `armeabi-v7a` / `x86_64` |
| 扩展名 | `apk` / `exe` / `zip` / `hap` 等 | `apk` |

**各平台命名示例**：

| 平台 | 类型 | 命名 |
| :--- | :--- | :--- |
| 安卓 | 通用 APK（含全部 ABI） | `SugarPaper-vX.Y.Z-android.apk` |
| 安卓 | 分 ABI APK | `SugarPaper-vX.Y.Z-android-arm64-v8a.apk` / `...-armeabi-v7a.apk` / `...-x86_64.apk` |
| Windows | 安装包（Inno Setup，自动更新校验用此包） | `SugarPaper-vX.Y.Z-windows-x64.exe` |
| Windows | 绿色版（解压即用） | `SugarPaper-vX.Y.Z-windows-x64.zip` |
| 鸿蒙 | 安装包（AppGallery 为主，GitHub 辅助分发） | `SugarPaper-vX.Y.Z-harmonyos.hap` |

**注意事项**：
- 构建产物默认名（`app-release.apk` / `SugarPaper.exe` 等）不含版本信息，上传前必须按上述格式重命名；
- 正式发布只上传 `--release` 正式包，不传 `--debug` 调试包；
- Android：同一 Release 内同平台同版本只保留一个通用包；分 ABI 上传时需在正文注明各包适用机型；
- Windows：安装包统一用 Inno Setup 生成的 `setup.exe` 重命名上传（未签名会有 SmartScreen 提示，属正常安全机制）；绿色版 zip 作为备选；

- 所有安装包建议同时附上 SHA-256 校验值，方便用户核对文件完整性。

## 🤝 多版本同步开发规范（S12 起强制）

> 详细规范见《S12 专注模式独立界面需求文档》第 4 节；本节为 README 层面的总则，适用于网页版 / 安卓版 / 微信小程序 / Windows / 鸿蒙所有平台版本。

1. **需求先行**：每个新功能（S 里程碑）必须先产出需求文档（命名带里程碑编号，放仓库根目录），再同时立项各平台开发。
2. **同步开发**：网页版与安卓版同一里程碑并行开发、同一轮验收，禁止一平台领先多个版本后才回补。
3. **同步版本号**：功能对齐时两平台版本号完全一致；安卓版以 `pubspec.yaml` 的 `version` 为唯一事实来源，网页版以 README 更新日志为基准；发布时 README / 代码版本号 / 安装包文件名三处一致。
4. **同步文档**：README 采用「单一 README · 多版本分区管理」，每个里程碑两平台各自的开发日志与 `#### vX.Y.Z` 更新日志**同时**补齐；需求文档在「📄 文档」章节登记。
5. **平台适配显式标注**：因平台特性无法对齐的能力（如 PWA 离线 vs 原生离线、拖拽排期 vs 上下移动）必须在 README 标注为「平台适配」，不得算作功能缺口。
6. **同步验收**：单元测试 / 端到端测试两平台各自维护；新功能必须有测试用例；发布前按需求文档功能清单逐项核对。

### 🏷 版本号更新体系（v0.30.0 起强制）

版本号固定为 **`v主版本.次版本.修订版本`**（如 `v0.30.0`），网页版 / 安卓版 / 未来各平台**永远同步同号**。版本号变更规则如下，任何发布都不得随意跳号：

| 版本类型 | 数字位 | 触发条件 | 示例 |
| :--- | :--- | :--- | :--- |
| **特大版本** | 主版本（第一位） | 重大里程碑 / 架构重构 / 不兼容变更 / 全新平台首发 | `v0.x.y` → `v1.0.0` |
| **大版本（功能版本）** | 次版本（第二位） | 新增功能 / 功能对齐 / 界面改版 | `v0.29.0` → `v0.30.0` |
| **小版本（修复版本）** | 修订号（第三位） | 仅修复 bug / 样式与文案微调 / 文档修订 | `v0.30.0` → `v0.30.1` |

执行规则：

1. **重要功能升大版本**：重要功能（新模块、界面改版、跨端新能力、用户可感知的大改进）升次版本（+1，修订号归零）。
2. **小功能 / 纯修复升小版本**：完成任意小功能、小优化，或 bug 修复、样式/文案微调、文档修订，修订号 +1（不升次版本）。
3. **即做即更，不攒批**：每完成一个功能（无论大小）立即升版本号、补版本日志并发布；禁止攒多个功能后一次性发布。
4. **不兼容变更升特大版本**：架构重构、破坏性数据格式变更、平台全新首发，主版本 +1（当前 `0.x` 阶段以 `1.0.0` 作为首个正式稳定版）。
5. **两端同步**：网页版 `APP_VERSION`、安卓版 `pubspec.yaml version`（含 build 号）、`updates/latest.json`、README 更新日志、安装包文件名五处必须一致。
6. **发布动作统一**：每次发版 = `git tag vX.Y.Z` + push → Actions 自动构建 APK（通用 + 分 ABI）、创建 Release、计算 SHA-256、回填 `updates/latest.json`、显式触发 Pages 部署。
7. **build 号规则（安卓）**：`version: X.Y.Z+build`，build 随每次大/小版本发布递增（当前 v0.32.0+51，下一版 +52）。
